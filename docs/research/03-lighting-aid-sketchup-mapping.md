## 1. 차용할 요소와 lighting-aid 대응표

| SketchUp 요소 | lighting-aid 적용 | 현재 앱의 대응 기능 |
|---|---|---|
| 캔버스 우선 레이아웃 (뷰포트 100%, UI는 플로팅 카드) | 무대 캔버스가 화면 전체를 차지하고, 패널은 모서리에 떠 있게 한다. | 고정 3단 레이아웃(280 / 가변 / 360px) |
| 좌측 세로 툴바 (아이콘, 활성 도구 강조) | **도구 레일**: 선택(V), 조명 배치(L), 조준(T), 셔터(S), Probe(P), 거리 측정(M), 메모(N), 화면 이동(H), 전체 보기(F) | 도구 개념 없이, 클릭한 대상에 따라 동작이 암묵적으로 결정됨 |
| 도구 검색 (🔍 → 긴 검색창) | **명령 검색 (Ctrl+K)**: 도구, 명령, 조명 이름을 한곳에서 검색 | 없음 |
| 우측 트레이 (아이콘 + 알약 라벨, 클릭하면 옆에 패널) | 조명 속성 / 조명 목록 / 조명기 라이브러리 / 밝기 Probe / 채널 패치 / 무대 설정 / 도면 레이어 / 도움말 | 우측 사이드바에 세로로 쌓인 섹션들 |
| 패널 문법 (제목 → 액션 아이콘 → 검색 → 목록) | 모든 패널을 같은 문법으로 통일 | 패널마다 구조가 다름 |
| 파일 헤더 (☰, 파일명, 실행 취소, "저장됨") | 프로젝트명 + 극장 정보 + Undo/Redo + 저장 상태 | 헤더에 무대 치수 입력과 저장 버튼이 섞여 있음 |
| 햄버거 → 파일 메뉴 슬라이드 | 홈으로 / 새 프로젝트 / 열기 / 다른 이름으로 저장 / 내보내기(.json, PNG, 큐시트 PDF, 패치 CSV) / 극장 변경 / 설정 / 인쇄 / 단축키 | 헤더의 "불러오기", "저장" 버튼 |
| 하단 상태 바: 도구 안내 문장 | 현재 도구의 사용법과 보조 키를 문장으로 안내 | 없음 (초보자 온보딩에 특히 유효) |
| 하단 VCB(수치 입력 상자) | 조준 중에는 **Tilt/Pan**, 배치 중에는 **X/Y**, 측정 중에는 **거리**를 직접 입력 | 속성 패널의 숫자 입력 |
| 홈 / 파일 목록 (썸네일 카드) | **프로젝트 허브**: 새 프로젝트(극장 템플릿 선택), 기기에서 열기, 극장에서 시작, 최근 프로젝트 카드 | 극장 선택 랜딩 카드 |
| 계정 드롭다운, 공유 버튼 | 클라우드 단계에서 도입 (로드맵 Phase 3~4) | 없음 |
| SSO 로그인 페이지 | Google 로그인 + "로그인 없이 시작(로컬 저장)" | 없음 |
| 장면(Scenes) 패널 | **씬 스트립**: 캔버스 하단에 큐 썸네일을 가로로 나열 (PowerPoint/SketchUp 장면 탭 절충) | 좌측 씬 목록 |

### 차용하지 않거나 변형한 것
- **3D 궤도(Orbit) 도구**: 현재 앱은 2D 평면도 도구이므로 넣지 않는다. 장기적으로 "단면/입면 보기" 탭을 추가할 여지는 남긴다.
- **우측 트레이의 항목 수**: SketchUp은 12개지만, lighting-aid는 7~8개로 줄였다. 초보자 대상이기 때문이다.
- **밝은 회색 뷰포트**: SketchUp은 밝은 하늘/지면을 쓰지만, 조명 도구는 빛이 잘 보여야 하므로 **어두운 캔버스 + 흰 플로팅 카드** 조합을 택했다.

## 3. 구현 로드맵 제안 (각 단계 = feature 브랜치 1개)

1. **`feature/editor-shell`**: 캔버스 우선 레이아웃 셸. 기존 패널 내용은 그대로 두고 플로팅 카드 + 우측 트레이로 옮긴다. 상태 바를 추가한다.
2. **`feature/tool-system`**: 도구 모드(`activeTool`)를 상태에 추가하고, 캔버스 마우스 처리를 도구별 핸들러로 분리한다. 단축키와 상태 바 안내 문장을 연결한다.
3. **`feature/scene-strip`**: 좌측 씬 목록을 하단 스트립으로 옮긴다. 썸네일 생성은 드래그가 끝났을 때만 하도록 지연(debounce)한다.
4. **`feature/command-palette`**: Ctrl+K 명령 검색.
5. **`feature/project-hub`**: 문서 모델(`Project { meta, stage, cues }`)과 UI 상태를 분리하고, 홈 화면과 최근 프로젝트(localStorage/IndexedDB)를 만든다.
6. **`feature/cloud-save`**: 로그인 + 클라우드 저장 (BaaS 선정 후).

### 기술적 선행 과제
- UI를 컴포넌트 단위로 나누려면, 지금의 `innerHTML` 전체 재렌더 방식 대신 **경량 프레임워크(Preact, Lit, Svelte 등) 도입**을 검토할 가치가 있다. 플로팅 패널이 여러 개 동시에 열리고 입력 포커스를 유지해야 하기 때문이다. 다만 `GeometryEngine`과 `drawCueToContext`는 프레임워크와 무관하게 그대로 쓸 수 있다.
- 디자인 토큰을 `index.html` 인라인 스타일에서 `src/styles/tokens.css`로 옮긴다.
